# mindmap 구현 계획

## 범위와 데이터 흐름

M1–M4 이후 v2(방어기제·성격 모듈, 통합 지도, 부가 기능)가 구현되었습니다. v2 설계는 `docs/v2-design.md`를 따릅니다. 회원가입 없이 32개 Likert 샘플 문항 → 응답 확인 → 검증 → 결정적 점수 계산 → 점수와 계산 근거 화면으로 진행합니다. 상황형·서술형 문항 진행, 개인 분석 규칙, AI API 연결은 이후 단계입니다.

```text
data/questions.ts + types/psychology.ts
               ↓
          질문 화면 / 임시 응답
               ↓
         lib/scoring.ts
               ↓
         lib/analysis.ts
               ↓
       설명 API (M7, 선택적)
               ↓
        결과 / 지도 / 흐름도
```

질문 데이터, 계산 함수, 설명 구성, 화면을 분리합니다. 실제 계산 결과와 데모 데이터는 타입·모듈로 구분합니다. 문항과 채점 버전을 결과에 포함합니다.

## 확정된 계산 설계 (M2–M4)

Likert 응답 x는 정수 0–4로 검증합니다. 역채점 문항은 4-x로 바꿉니다. 차원 d의 기본 점수는 `round(100 × Σ(w × x) / (4 × Σw))`로 정규화합니다. 가중치 w는 양수이며 문항 데이터에 정의합니다. 미응답을 0으로 대체하지 않습니다. 필수 문항이 누락되면 계산을 거부합니다.

초기 문항은 **차원별 4개, 총 32개**입니다. 각 차원에 역채점 문항 1개가 있고 모든 가중치는 1입니다. 질문지 버전은 `selfmap-likert-32-v1`, 채점 버전은 `weighted-likert-v1`입니다. 자기이해용 샘플이며 검증된 임상 척도가 아닙니다. 높은 회복 점수와 높은 자기비판 점수를 같은 가치 기준으로 평가하지 않습니다. 총점·백분위·유형·진단을 산출하지 않습니다.

상황형 선택은 차원별로 고정된 가중치를 매핑하되, 하나의 선택으로 특정 차원을 과도하게 올리지 않습니다. M8에서 범위가 정해진 보정(제안 ±10점 이내)을 적용하고 0–100으로 제한합니다. 보정 범위는 검토 후 확정합니다. 선택지 A–E를 무조건 좋은/나쁜 반응의 순서로 채점하지 않습니다. 잠시 멈추는 선택도 맥락 없이는 회복 능력으로 단정하지 않습니다.

서술형 응답은 수치 계산에 사용하지 않습니다. LLM은 가능한 감정·욕구·자동 해석·행동 표현을 원문 근거와 함께 구조화합니다. 자기이해 설명은 가설로 제시하며 사용자가 맞지 않는다고 느낄 수 있음을 허용합니다.

## 상태와 저장

M3에서는 탭 단위 sessionStorage를 사용합니다. 버전·문항 ID·응답 범위·현재 문항 번호·완료 상태를 복원 시 다시 검증합니다. 응답 삭제 시 해당 저장 키와 메모리 상태를 함께 초기화합니다. 저장 기능이 차단되면 메모리에서 진행하고 새로고침 복구가 불가능함을 안내합니다. 공유 기기에서는 같은 탭에 응답이 남을 수 있으므로 저장 방식과 삭제 방법을 명시합니다. 서버·DB 저장은 연결하지 않습니다.

M1의 Prisma 스키마는 임시 세션 저장을 위한 기반입니다. 서버 저장을 사용할 경우 명시적 고지, 만료 정책, 세션별 접근 검증을 먼저 구현합니다. 회원가입 없이 사용한다는 것이 서버에서 익명 데이터를 영구 저장한다는 뜻은 아닙니다.

## 설명 생성

점수와 채점 버전은 계산 엔진이 소유합니다. LLM 응답에는 점수 필드를 허용하지 않고 설명용 필드만 검증합니다. 서술형 텍스트는 데이터로 전달하고 지시로 실행하지 않습니다. 임의 외부 API 전송은 M1에 포함하지 않습니다. M7 연결 시 전송 범위와 동의를 UI에 명시합니다.

설명은 상황 → 자동 해석 → 감정 → 핵심 욕구 → 행동 경향 → 회복 구조를 따릅니다. 실제로 답하지 않은 몸의 변화나 행동은 경험 사실로 서술하지 않습니다. 점수만으로 구체적 행동을 확정하지 않습니다. 규칙 기반 기본 설명이 항상 사용 가능해야 합니다.

## 검증

모든 단계에 타입·린트·프로덕션 빌드를 적용합니다. M1은 화면과 상호작용을 확인하고, 계산 테스트는 M4에서 경계·역채점·누락 등 의미 있는 불변식을 중심으로 추가합니다. API·보정은 해당 단계에서 오류 및 권한 경계를 검증합니다.
