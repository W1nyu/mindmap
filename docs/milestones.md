# Milestone 기록

## M1 — 프로젝트 구조 및 UI

### 구현 내용

- Next.js App Router, TypeScript strict, Tailwind CSS 설정.
- 아이보리·청록색 반응형 공통 화면, 메뉴 현재 위치 표시, 키보드 포커스, 본문 바로가기.
- `/`: 서비스 소개, 8개 차원, 정적 SVG 지도 예시와 반응 흐름.
- `/questions`: 0–4 선택과 초기화가 가능한 기본 문항 UI 예시. 서버 전송·저장·채점 없음.
- `/results`: 가상 지도·점수·특징·상호작용·강점·주의점·전략·반응/회복 흐름.
- Prisma 6·SQLite 임시 세션 기본 스키마. 데이터베이스 저장은 미연결.
- 실제 문항, 계산, 설명 모듈의 경계와 후속 구현 위치 확보.

### 변경된 파일

`app/`, `components/`, `data/`, `lib/`, `types/`, `prisma/schema.prisma`, `docs/`, `README.md`, `package.json`, 설치 lockfile 및 TypeScript·Next.js·PostCSS·ESLint 설정, `.gitignore`, `.env.example`.

### 실행 방법

```powershell
npm install
npm run dev
```

`http://localhost:3000`에서 세 화면을 확인합니다. DB나 API 키 없이 실행할 수 있습니다.

## M2–M4 — 샘플 설문과 결정론적 채점

2026-10-07 구현 완료. 사용자 요청에 맞춰 M1의 구조와 디자인을 이어서 구현했습니다.

### M2: 데이터와 타입

- 8개 차원 ID의 단일 정의, Likert·상황형·서술형 질문과 응답의 discriminated union, 점수·근거·세션 타입.
- 차원별 4개, 총 32개 한국어 Likert 샘플 문항. 각 차원에 역채점 1개, 모든 가중치는 1.
- 질문지 버전 `selfmap-likert-32-v1`. 문항 ID·내용·차원 커버리지·역채점·가중치 검증.
- 상황형·서술형은 타입 계약만 정의했으며 질문 진행이나 채점에 연결하지 않았습니다.

### M3: 질문 UI

- 0–4 라디오 선택, 완료 응답 수와 진행률, 이전·다음, 응답 수정, 제출 전 32개 응답 확인.
- 미응답 상태에서 다음 이동 및 제출 방지. 0점은 유효한 응답으로 취급.
- sessionStorage에 응답과 현재 질문 위치를 저장하고 새로고침 후 복원. 버전·ID·범위·완료 상태 재검증.
- 응답 삭제 확인과 초기화. 저장 차단 시 메모리 진행 및 새로고침 제한 안내.
- 서버·DB·AI API로 응답을 전송하지 않습니다.

### M4: 채점과 결과

- `lib/scoring.ts` 순수 함수: 역채점 → 차원별 가중 평균 → 0–100 정규화 → 반올림.
- 채점 버전 `weighted-likert-v1`, 차원별 원응답·채점값·역채점·가중치·합계 근거.
- 누락·중복·잘못된 ID·비정수·범위 밖 응답·잘못된 문항 데이터를 거부.
- `/results`: 완료 응답으로 계산한 8개 차원 점수. `/results?example=1`: 고정 mock 응답을 같은 엔진으로 계산한 예시.
- 강점과 어려움은 차원별 일반 안내이며, 개인 분석 규칙·상호작용·전략 생성은 적용하지 않았습니다.
- 결과는 경향이며 진단·고정된 유형·백분위가 아님을 명시했습니다.

- 직접 작성한 `public/sw.js`(의존성 없음): 핵심 14개 화면 미리 캐시, 이동은 네트워크 우선 → 캐시 → 홈, `/_next/static`·아이콘은 캐시 우선, `/api/` 제외. 프로덕션에서만 등록, 오프라인 안내 띠.
- 보안 헤더 추가(nosniff, X-Frame-Options DENY, Referrer-Policy, Permissions-Policy)와 `sw.js` 무캐시·CSP.
- 검증: 실제 Edge(헤드리스, DevTools 프로토콜)로 등록·활성화·14개 캐시·페이지 제어 확인 후 네트워크를 오프라인으로 바꿔 /journal, /learn, /results?example=1, /questions/defense가 오프라인 띠와 함께 열리는 것 확인. 데스크톱 앱의 내장 브라우저 창은 서비스 워커 스크립트를 가져오지 못하는 제한이 있어 그곳에서는 등록되지 않음(앱 문제 아님).

## v3.7 — 주간 돌아보기와 시작 경로

- `/review`: 월–일 단위로 마음 기록 수·활동한 날·평균 강도(지난주 대비)·가라앉은 정도·자주 기록한 감정과 욕구·알아차린 방어·해 본 실천·저장한 결과를 요약하고 한 주를 돌아보는 질문 제시. 이전·다음 주 이동(미래 주 비활성). `lib/weekly.ts` 순수 함수, 로컬 날짜 경계.
- 홈 ‘어떻게 시작할까요?’: 가볍게 3분(애착) / 기본 15분(성격→반응→방어) / 한 주 동안(전 모듈+상황 반응+매일 기록+주간 돌아보기).
- 사이드바에 주간 돌아보기, 마음 기록 통계 아래 바로가기, 서비스 워커 캐시 버전 v2와 /review 미리 캐시.
- 검증: test 71개(주 범위·월요일 경계·범위 내 집계·활동일·강도 변화), typecheck·lint·build(24개 경로), 브라우저에서 두 주 데이터로 요약·주 이동·빈 주 확인 후 테스트 데이터 삭제.

## v3.8 — 내가 동의한 문장, 공유 링크

- 모든 모듈 결과에 ‘내가 강하게 동의한 문장’(원응답 3 이상, 최대 5개, 동률은 문항 순서, 반대 방향 문항 안내). 결과의 계산 근거에서 응답을 복원하는 `moduleResponses`(복원 후 재채점이 원래 결과와 같음을 테스트).
- 공유 링크: 응답을 URL 조각에 담아 서버 전송 없이 공유, `/shared`에서 읽기 전용 마음 지도로 재계산. 마인드맵 비대화형 모드, 공유되지 않은 모듈 표시, 검색 제외·no-referrer 메타.
- 검증: test 76개, typecheck·lint·build(25개 경로), 브라우저에서 공유 링크 생성·열기·잘못된 링크 오류 확인.
